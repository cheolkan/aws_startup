AWS Security Agent의 Pen-test 기능을 2026년 10월 26일(월) 오프라인 핸즈온 워크숍 또는 셀프 핸즈온 워크숍 콘텐츠 중 편한 방식으로 직접 실행해 보세요. 결과 리포트를 Security SA와 Account Team에 공유해 주시면, 별도 일정의 Security SA Office Hour에서 개선 방안과 궁금한 점을 함께 정리해 드립니다.

Why now

공격 기법은 진화하고, 점검은 연례 행사에 머물러 있습니다

최근 보안 사고는 단순한 패턴을 넘어 SSRF(서버 측 요청 위조), 패치되지 않은 웹 서버 취약점 악용 등으로 진화하고 있습니다. 인터넷에 공개된 서비스를 겨냥한 자동화 스캔도 점점 정교해지고 있습니다.

정부와 관계 기관도 기업에 웹·API 취약점 점검과 접근 권한 관리 강화를 권고하고 있습니다. 스타트업은 배포가 잦아 새로운 API가 계속 생기지만, 외부 모의해킹을 자주 하기는 어렵습니다.

About

AWS Security Agent란

애플리케이션 보안을 설계부터 배포까지 지원하는 AWS의 AI 에이전트 서비스입니다. 테스트 대상과 범위를 지정하면 에이전트가 정찰부터 공격 경로 검증까지 수행하고, 재현 단계와 조치 가이드를 포함한 결과를 제공합니다. 소스 코드와 API 명세를 함께 제공하면 이를 참고해 테스트하며, CI/CD 파이프라인에 연결해 반복 실행할 수도 있습니다.

요금: 공식 요금 페이지 · 서비스 소개: AWS Security Agent
Coverage · Dev + Runtime

배포 전과 배포 후를 함께 점검합니다

공개 서비스의 취약점과 AWS 계정의 설정 문제는 함께 악용되는 경우가 많습니다. 이번 프로그램은 개발 단계와 운영 환경을 나눠 점검하고, 두 영역이 겹치는 구간에서 한 번 더 검증합니다.

기획·요구사항 설계·프로토타입 개발·테스트 배포·운영
위협 모델링 SAST · SCA · DAST · Pen-test 취약점 관리
A

개발 영역 — AWS Security Agent
코드와 설계를 대상으로 위협 모델링, 코드 보안 점검(SAST·SCA), PR 코드 리뷰, Pen-test를 수행합니다. 저장소와 배포 전 산출물에서 문제를 일찍 찾는 데 초점을 둡니다.

B

운영 영역 — Startup Security Baseline
배포된 AWS 계정을 대상으로 IMDSv2 적용, IAM 최소 권한, Amazon Bedrock 호출 로깅, Amazon GuardDuty, 비용 알람 등 기본 보안 설정을 점검합니다.

두 영역이 겹치는 Pen-test · DAST · 취약점 관리 구간은 배포 전과 후에 모두 점검해 지속적으로 검증합니다.

예시로 보면

①

코드에 하드코딩된 키
개발 단계에서 Security Agent의 코드 점검과 코드 리뷰로 찾아냅니다.

②

IMDSv1을 노린 SSRF
두 영역이 함께 막습니다. Startup Security Baseline으로 IMDSv2를 강제해 예방하고, Security Agent Pen-test로 실제로 도달 가능한지 검증합니다.

Security Agent의 일부 기능은 Preview 단계일 수 있습니다. 각 서비스의 요금과 무료 체험 조건은 서비스별 공식 페이지를 확인해 주세요.

Before you start

Pen-test 실행 전 확인해 주세요

  • Pen-test는 귀사가 소유하고 테스트 권한을 가진 애플리케이션에만 실행할 수 있습니다.
  • Production 환경에서 실행할 때는 테스트 시간대, 대상 범위, 모니터링 담당자를 미리 정하고 사내 관련 부서와 공유해 주세요.
  • 테스트 실행 리전과 데이터 처리 방식은 공식 문서에서 확인하고, 사내 보안 정책에 맞는지 검토해 주세요.
  • 결과 보고서에는 취약점 정보가 담겨 있습니다. Pen-Test 결과 파일에는 비밀번호를 걸어 Account Team(Sales/SA) 와 leejiyou@amazon.com 으로 전달 부탁드립니다.
  • AI Pen-test 결과는 담당자 검토를 거쳐 활용하시기 바랍니다.
